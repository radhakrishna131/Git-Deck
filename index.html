Setup & Configuration

Config
git config
Set configuration values

Get and set repository or global Git options. Configure your identity, editor, aliases, and behaviors. Settings cascade: local → global → system.

--global --local --system --list --unset
git config --global user.name "Ada Lovelace"
git config --global user.email "ada@example.com"
git config --list # view all settings
Use --global for machine-wide settings, omit for repo-only.
Config
git config alias
Create command shortcuts

Define abbreviations for commonly used commands. Aliases reduce keystrokes and allow you to create custom compound commands.

--global alias.*
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.lg "log --oneline --graph"
Prefix with ! to run shell commands as aliases.

Init & Clone

Init
git init
Create a new repository

Initializes a new Git repository by creating a .git subdirectory. This sets up the version-control infrastructure for any project from scratch.

--bare --initial-branch=<name> --quiet
git init # current directory
git init my-project # new folder
git init --bare repo.git # server-side
--bare repos have no working tree — ideal for shared servers.
Init
git clone
Copy an existing repository

Creates a full copy of a remote repository, including all history, branches, and tags. Automatically sets up the origin remote.

--depth=<n> --branch <name> --single-branch --recurse-submodules
git clone https://github.com/user/repo.git
git clone --depth 1 <url> # shallow clone
git clone -b main <url> my-dir
--depth 1 gives a fast shallow clone with only latest snapshot.

Staging & Snapshot

Stage
git add
Stage changes for commit

Moves changes from the working directory to the staging area (index). Gives you precise control over what goes into the next commit snapshot.

-A / --all -p / --patch -u -n / --dry-run
git add README.md # single file
git add . # all in current dir
git add -p # interactive patch mode
Use -p to stage only specific hunks within a file.
Stage
git commit
Record staged snapshot

Records the staged changes as a new commit in the repository history. Each commit requires a message and creates an immutable snapshot with a unique SHA-1 hash.

-m "<msg>" -a --amend --no-edit -S
git commit -m "feat: add login page"
git commit -am "fix: typo" # add + commit
git commit --amend --no-edit # fix last
--amend rewrites the last commit — never amend pushed commits.
Stage
git status
Show working tree state

Displays the state of the working directory and staging area — which changes have been staged, which haven't, and which files aren't tracked.

-s / --short -b / --branch -u / --untracked
git status # full output
git status -s # short format
git status -sb # short + branch
XY codes in short mode: M=modified, A=added, ?=untracked.
Stage
git diff
Show file differences

Shows unstaged changes between your working directory and the index. Compare branches, commits, or specific files. Essential for reviewing before staging.

--staged --stat --name-only --word-diff
git diff # unstaged changes
git diff --staged # staged vs last commit
git diff main feature-branch
--staged (or --cached) shows what will go into the next commit.
Stage
git rm
Remove files from index

Removes files from both the working tree and the staging index. Use --cached to stop tracking without deleting the local file.

--cached -r --force -n / --dry-run
git rm file.txt # delete + untrack
git rm --cached secret.env # untrack only
git rm -r --cached node_modules/
After --cached, add the file to .gitignore to prevent re-tracking.
Stage
git mv
Move or rename tracked files

Moves or renames a file and stages the change in one step. Equivalent to mv + git rm + git add but Git tracks the rename properly.

-f / --force -n / --dry-run
git mv old-name.txt new-name.txt
git mv src/utils.js lib/helpers.js
Git detects renames in logs even if you use plain mv + add.
Stage
git stash
Shelve uncommitted work

Temporarily stores modified tracked files, giving you a clean working directory. Useful when switching context without committing incomplete work.

push -m "<msg>" pop apply list drop --include-untracked
git stash push -m "wip: login form"
git stash list # see all stashes
git stash pop # restore latest
git stash apply stash@{2}
pop = apply + drop. Use apply to keep the stash entry intact.
Stage
git tag
Mark a specific commit

Creates a named reference to a specific commit, typically for marking release points. Annotated tags are full objects with messages; lightweight tags are simple pointers.

-a -m "<msg>" -l -d --sort=-version:refname
git tag v1.0.0 # lightweight
git tag -a v2.0.0 -m "Release 2.0"
git tag -l "v*" # list all v* tags
git push origin --tags
Tags are not pushed by default — always use git push --tags.

Branching

Branch
git branch
List, create, delete branches

Manages branches in the repository. Branches are lightweight movable pointers to commits that enable parallel development without affecting the main codebase.

-a -d / -D -m -r --merged --no-merged
git branch # list local branches
git branch feature/login # create
git branch -d feature/login # safe delete
git branch -m old-name new-name
-D force-deletes; use only when -d warns about unmerged commits.
Branch
git checkout
Switch branches or restore files

Switches the working directory to a different branch or restores working tree files. The classic multi-purpose command — split into git switch and git restore in newer Git.

-b <branch> -- -t / --track --orphan
git checkout main # switch branch
git checkout -b feature/api # create + switch
git checkout -- file.txt # discard changes
Prefer git switch (Git 2.23+) for clarity — it only changes branches.
Branch
git switch
Switch branches (Git 2.23+)

The modern, dedicated command for changing branches. Clearer than git checkout — it only switches branches and cannot accidentally modify files.

-c <branch> --detach -
git switch main # switch
git switch -c feature/dashboard # create + switch
git switch - # back to previous branch
git switch - is a quick toggle between the last two branches.

Merge & Rebase

Merge
git merge
Integrate branch histories

Combines the history of two branches. Creates a merge commit that preserves both branch histories. Fast-forward merges occur when no diverging commits exist.

--no-ff --ff-only --squash --abort --strategy=<s>
git merge feature/login # fast-forward
git merge --no-ff feature/api # force merge commit
git merge --squash feature # squash all commits
--no-ff preserves feature branch topology in history.
Merge
git rebase
Reapply commits on new base

Moves or combines a sequence of commits to a new base commit, creating a linear project history. More powerful (and riskier) than merging for cleanup.

-i / --interactive --onto <base> --abort --continue --skip
git rebase main # rebase onto main
git rebase -i HEAD~3 # interactive, last 3
git rebase --abort # cancel
Never rebase commits already pushed to shared branches.
Merge
git cherry-pick
Apply specific commits

Applies the changes introduced by specific commits onto the current branch. Useful for backporting fixes or selectively applying changes across branches.

-n / --no-commit -e --abort --continue <hash>..<hash>
git cherry-pick a1b2c3d # single commit
git cherry-pick a1b..e5f # range
git cherry-pick -n abc123 # without committing
Creates a new commit with the same changes but a different SHA.

Remote Operations

Remote
git remote
Manage remote connections

Manages the set of remotes (other repositories) whose branches you track. origin is the conventional name for the primary remote repository.

add <name> <url> remove rename -v set-url
git remote -v # list with URLs
git remote add origin https://github.com/user/repo.git
git remote set-url origin <new-url>
A repo can have multiple remotes — useful for open-source forks.
Remote
git fetch
Download without integrating

Downloads objects and refs from a remote repository into your local tracking branches, but does not merge them. Safe to run at any time — never modifies your working directory.

--all --prune --tags --depth=<n>
git fetch origin # fetch from origin
git fetch --all --prune # all remotes + clean
git fetch origin main
--prune removes local tracking branches for deleted remotes.
Remote
git pull
Fetch and integrate

Fetches from a remote and immediately merges (or rebases) into the current branch. Essentially git fetch + git merge in one step.

--rebase --ff-only --no-commit --squash
git pull origin main # fetch + merge
git pull --rebase # rebase instead
git pull --ff-only # fail if not FF
--rebase keeps a cleaner linear history vs merge commits.
Remote
git push
Upload local commits

Uploads local branch commits to the remote repository branch. Transfers the history and updates the remote ref. Fails if the remote has diverged.

-u / --set-upstream --force-with-lease --tags --delete --dry-run
git push origin main # push to remote
git push -u origin feature # set tracking
git push --force-with-lease # safe force
--force-with-lease is safer than --force: fails if remote changed.

Undo & Fix

Undo
git reset
Reset HEAD to a state

Moves HEAD and optionally the index/working tree to a specified state. Three modes: --soft (keep staged), --mixed (unstage, keep files), --hard (discard everything).

--soft --mixed --hard HEAD~<n> <commit>
git reset --soft HEAD~1 # undo commit, keep staged
git reset HEAD~1 # unstage (mixed default)
git reset --hard HEAD~1 # ⚠ discard all
--hard is destructive and permanent. Back up or use reflog to recover.
Undo
git revert
Safely undo a pushed commit

Creates a new commit that undoes the changes from a specified commit. Unlike reset, it's safe for shared/public branches because it adds rather than removes history.

--no-commit -e / --edit -n
git revert abc1234 # revert one commit
git revert HEAD~3..HEAD # revert range
git revert --no-commit abc1234
Prefer revert over reset for anything already pushed to shared branches.
Undo
git restore
Restore working tree files (Git 2.23+)

Restores files in the working tree from the index or a commit. The modern replacement for git checkout -- <file>. Use --staged to unstage files.

--staged --source=<tree> -W / --worktree
git restore file.txt # discard changes
git restore --staged file.txt # unstage
git restore --source HEAD~2 file.txt
--staged unstages without discarding the working tree changes.
Undo
git clean
Remove untracked files

Removes untracked files from the working directory. Useful for cleaning build artifacts, generated files, or anything not under version control.

-f / --force -d -n / --dry-run -x -i
git clean -n # preview what'd be removed
git clean -fd # force + directories
git clean -fdx # include .gitignored
Always run -n (dry-run) first — clean is irreversible.

Inspect & Log

Inspect
git log
Browse commit history

Shows the commit history for the current branch. Highly customizable with format strings, filtering by author/date/file, and graph display. One of the most-used inspection tools.

--oneline --graph --all --author=<name> -n <limit> --since / --until
git log --oneline --graph --all
git log -n 10 --author="Ada"
git log --since="2 weeks ago" --stat
Alias git lg to --oneline --graph --decorate --all for daily use.
Inspect
git show
Show object details

Displays information about a Git object — commit changes, tag messages, tree contents, or blob data. For commits, shows the diff introduced by that commit.

--stat --name-only --format=<fmt> -s
git show abc1234 # show commit diff
git show HEAD:src/app.js # file at commit
git show v2.0.0 # show tag info
HEAD:path syntax shows a file as it was at any commit.
Inspect
git blame
Show line-by-line authorship

Annotates each line of a file showing which commit and author last modified it. Invaluable for tracking when and why specific lines changed — not for blame, but for context.

-L <start,end> -C -w --since=<date>
git blame README.md
git blame -L 10,25 app.js # lines 10–25
git blame -w -C src/utils.js
-C detects lines moved/copied from other files in the same commit.
Inspect
git reflog
Local operations log

Records when the tip of branches and other references were updated. Your safety net — lets you recover commits lost from reset, rebase, or deleted branches.

--all --date=relative expire delete
git reflog # all recent HEAD changes
git reflog --all --date=relative
git reset --hard HEAD@{3} # go back
Reflog entries expire after 90 days. Always your first recovery tool.
Inspect
git grep
Search tracked files

Searches through the content of tracked files using patterns, much like Unix grep but Git-aware. Can search across commits, branches, and the index — not just working tree.

-n -i -l -c -E
git grep "TODO" # search working tree
git grep -n "function login"
git grep "console.log" HEAD~5
Faster than grep -r because it only searches tracked files.
Inspect
git shortlog
Summarize commit history

Groups commits by author with a count and list of subject lines. Ideal for generating changelogs and contributor summaries for releases.

-s -n -e --no-merges
git shortlog -sn # ranked contributors
git shortlog -sne HEAD~20..HEAD
git shortlog --no-merges
-sn gives a ranked leaderboard of contributors by commit count.

Advanced

Advanced
git bisect
Binary search for bugs

Uses binary search to find the commit that introduced a bug. You mark commits as good or bad; Git checks out the midpoint until it isolates the culprit. Can be automated with a test script.

start good <hash> bad <hash> run <script> reset
git bisect start
git bisect bad HEAD
git bisect good v2.0.0
git bisect run npm test # automate
Automated bisect via run can test thousands of commits hands-free.
Advanced
git submodule
Embed repos within repos

Allows you to keep a Git repo as a subdirectory of another repo. Useful for including libraries as tracked dependencies. Each submodule points to a specific commit in the child repo.

add <url> update --init --recursive foreach status
git submodule add https://github.com/org/lib.git lib
git submodule update --init --recursive
git submodule foreach git pull
After cloning a parent repo, always run update --init --recursive.
Advanced
git worktree
Multiple working directories

Creates additional working trees linked to the same repository. Lets you check out multiple branches simultaneously without stashing — perfect for comparing or hotfixing while in the middle of work.

add <path> <branch> list remove prune
git worktree add ../hotfix-1.2 hotfix/1.2
git worktree list
git worktree remove ../hotfix-1.2
Each worktree is a separate directory but shares the same .git history.
Advanced
git filter-repo
Rewrite repository history

The recommended tool (replacing filter-branch) for rewriting Git history at scale — remove large files, strip secrets, split or merge repos. Requires separate install but is dramatically faster.

--path <file> --invert-paths --path-rename --mailmap
git filter-repo --path secret.env --invert-paths
git filter-repo --path src/ # keep only src/
After history rewrite, all collaborators must reclone. Force-push required.
Advanced
git archive
Export a snapshot as archive

Creates a tar or zip archive of a specific tree or commit. Unlike cloning, the output contains only the file tree without any Git metadata — perfect for deployment artifacts.

--format=zip --prefix=<dir>/ --output=<file> --remote=<url>
git archive --format=zip HEAD > release.zip
git archive --prefix=project/ -o v1.tar.gz v1.0.0
Use export-subst in .gitattributes to embed metadata in archived files.
Advanced
git gc
Garbage collect & optimize

Runs a number of housekeeping tasks — packs loose objects, prunes unreachable objects, compresses pack files, and optimizes the repository for speed and size.

--aggressive --prune=now --auto --quiet
git gc # standard cleanup
git gc --aggressive # deep optimization
git gc --prune=now # remove all loose objs
Run periodically on large repos; --aggressive takes much longer but compresses better.
Advanced
git bundle
Pack repo into a single file

Packages a repository's objects and refs into a single binary file. Useful for offline transfer, backups, or sharing when network access to the remote isn't available.

create <file> verify unbundle list-heads
git bundle create repo.bundle --all
git clone repo.bundle my-repo
git bundle verify repo.bundle
A bundle can be cloned from directly: git clone repo.bundle.
Advanced
git notes
Attach extra metadata to commits

Adds, removes, or reads notes attached to objects in the repository. Notes are like sticky annotations on commits without modifying the commit itself — useful for CI results or review status.

add -m "<msg>" show remove list
git notes add -m "Reviewed by: Ada" HEAD
git notes show HEAD
git push origin refs/notes/commits
Notes are stored in refs/notes and must be explicitly fetched/pushed.
